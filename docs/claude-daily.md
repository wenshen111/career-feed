# Claude 每日情报 · 工作手册

每天意大利时间 07:47，Claude 的定时任务按这份手册写 `feed-claude.json`。
闻神的个人背景（专业、技能、证件、关注的路线）**不写在这个公开仓库里**，只写在定时任务自己的指令里。

## 步骤

1. 拉最新的 `main`。
2. 读 `feed-gpt.json` 和 `feed-claude.json`，记下双方最近 30 天已经发过的情报和待办。
3. 搜索今天的新机会（见下面的“找什么”）。每一条都要**打开原始页面核实**：标题、机构、地点、报酬、截止日期、硬门槛（语言、学历、国籍或签证、工作年限）。只看到聚合站转述、没打开原页的，不发。
4. 把通过核实的写进一个临时候选文件（**不要放进仓库目录**），例如 `/tmp/candidates.json`：

   ```json
   {
     "items": [
       { "kind": "工作", "title": "…", "org": "…", "loc": "…", "pay": "…", "deadline": "2026-12-15",
         "imp": 4, "why": "…", "link": "https://…" }
     ],
     "todos": [ { "t": "…", "due": "2026-12-01", "why": "…", "rel": "可选" } ],
     "note": "今天给她的一句话"
   }
   ```

   和 GPT 已发的是同一件事、但你有新角度时，加 `"newAngle": "只写新角度的那一句"`；没有新角度就别放进来，脚本也会拦。
5. 运行：

   ```
   node scripts/update_feed_claude.mjs --candidates /tmp/candidates.json
   node scripts/validate.mjs
   node scripts/check_links.mjs
   ```

   校验不过就改候选文件重跑，不要手改 `feed-claude.json` 绕过脚本。
6. 只提交 `feed-claude.json`，提交信息：`情报：YYYY-MM-DD`。推送到 `main`，推送失败先 `git pull --rebase` 再推，最多 3 次。
7. 最后的回复（会变成给她手机的推送）用中文，三行以内：今天几条、最重要的一条是什么、截止最近的是哪天。

## 找什么

按 `kind` 分七类，每天不用每类都有：

| kind | 找什么 |
| --- | --- |
| 工作 | 正式岗位：三维记录、摄影测量、无人机测绘、GIS、商业考古、博物馆教育、文化遗产咨询 |
| 兼职 | 短期合同、自由职业、按天计费的测绘或记录项目、发掘季的技术员 |
| 学校 | 带薪博士岗、暑期学校、培训课程、证书 |
| 联合国 | 联合国系统和其他国际组织的岗位、实习、YPP |
| 资助 | 奖学金、研究经费、创业资助、旅行资助 |
| 比赛 | 征文、摄影、可视化、数字遗产相关的比赛和奖项 |
| 热点 | 会影响她路线的政策和行业变化：签证门槛、工资线、大项目开工、新法规 |

## 质量规则

- **宁缺毋滥**：一天 3–8 条，没有合格的就发 0 条，`note` 里说一句“今天没有值得发的”。
- **不发过期的**：截止日期离今天不到 3 天的不发（除非 imp 5，并在 `why` 里写清楚时间）。
- **硬门槛要写出来**：要德语 C1、要本国国籍、不担保签证，这些写进 `why`，不要藏。
- **`why` 是 Claude 自己的看法**：一句话，具体到“哪项经历对口”或“哪个门槛卡人”，不夸、不鼓劲。
- **`imp`**：5 = 非常对口且现在就该投；4 = 对口；3 = 值得看；2 = 边缘；1 = 只是知道一下。
- **待办**：0–3 条，必须是今天能动手的具体动作，带截止日期。
- **`adj`**（只有 Claude 写）：只有看到实打实的新证据（例如门槛变了、某条路线一下子出现很多岗位）才改，一次 ±1–3，原因写进 `note`。不确定就不改。
- **不放个人数据**：情报里不写她的成绩、收入、证件号、住址。
